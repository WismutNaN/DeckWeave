# ADR-0005: Ошибки и изоляция отказов

**Дата:** 2026-10-11  
**Статус:** Принято

## Контекст

Публичная plugin ecosystem означает непредсказуемые crash, hangs, несовместимые versions и потерю устройств. Ошибка одного расширения не должна останавливать остальные workspaces или оставлять бесконечную очередь.

## Рассматриваемые варианты

1. **Fail-fast всего host** — упрощает разработку, но неприемлем для фонового контроллера.
2. **Игнорировать ошибки и продолжать** — скрывает потерю команд и повреждение состояния.
3. **Изолировать runtime, маркировать degraded state, ограниченно перезапускать** — явное частичное продолжение.

## Решение

Выбрали **process isolation, structured errors, deadlines, bounded queues, session generations и restart с backoff/circuit breaker**. Применение профиля использует plan и сохраняет последнюю рабочую revision; late messages старой session отклоняются.

## Последствия

**Становится проще:** локализовать crash и показывать точное состояние пользователю.  
**Становится сложнее:** каждый модуль должен определять cancellation и recovery semantics.  
**Закрывает дверь на:** `unwrap` на внешних данных и неограниченные каналы в runtime paths.
