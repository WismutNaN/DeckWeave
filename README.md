# DeckWeave

> Локальная модульная платформа, которая объединяет физические, виртуальные и удалённые устройства с приложениями, автоматизациями и визуальной обратной связью.

DeckWeave не является программой только для Stream Deck-подобных панелей. Рабочее пространство может одновременно включать клавиатуры, геймпады, N4 Pro, сенсорные поверхности, виртуальные устройства, приложения и будущие удалённые узлы. Конкретное оборудование, интеграции и тяжёлые функции подключаются плагинами; ядро хранит общую модель возможностей, состояний и связей.

Первый практический результат проекта — ежедневно пригодная конфигурация Mirabox N4 Pro на Windows. Архитектура при этом сразу учитывает клавиатуры, геймпады, OpenAction/Elgato-плагины, Linux, Android/Steam Deck agents и отдельный low-latency media runtime.

## Статус

Проект находится на стадии утверждённой архитектурной спецификации. Исполняемый код ещё не создан. Реализация начинается с [Фазы 1 — Скелет](docs/PLAN.md#фаза-1--скелет-репозитория).

## Принципы

- ядро не содержит VID/PID и команд конкретных устройств;
- устройство одновременно может быть источником событий и получателем команд;
- простое назначение делается напрямую на цифровом представлении устройства, сложное раскрывается как graph;
- плагины индексируются без запуска и активируются только при необходимости;
- один сбойный plugin package не останавливает host;
- UI, control plane и real-time media имеют разные контуры исполнения;
- всё, что делает UI, доступно через версионированный application API;
- совместимость с OpenAction/Elgato реализуется bridge-слоем, а не ограничивает внутреннюю модель;
- Windows 10/11 поддерживается первой, Linux — следующей; macOS учитывается в контрактах;
- профиль переносим между ОС, если все используемые contributions доступны на целевой платформе.

## Лицензирование

Подтверждённая стратегия: приложение и core — `GPL-3.0-or-later`; спецификации протоколов, SDK и минимальные примеры плагинов — `MIT OR Apache-2.0`. Лицензия каждого package должна быть указана отдельно. До добавления исходного кода стратегия остаётся архитектурным решением, а не юридической гарантией совместимости всех будущих заимствований.
